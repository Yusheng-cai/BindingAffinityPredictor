Boltz-2: what the model is doing

Think of Boltz-2 as an end-to-end graph of learned modules: sequence/SMILES + MSA + chemistry -> token graph -> pairwise stack -> structure diffusion -> confidence and affinity heads.

Inputs
Protein sequence + optional MSA, ligand SMILES/CCD, optional templates/constraints
Tokenization and feature construction
Build per-token single features and per-token-pair features (z), then masks for padding, contacts, affinity target, bonds, etc.
Trunk + Pairformer stack
Uses attention-style modules (s/z) with residue/atom pair context, relative-position encoding, and optional MSA/template channels.
Diffusion conditioner + AtomDiffusion module
Samples 3D atom coordinates for the whole complex simultaneously.
Heads
1) Confidence head (pLDDT/PAE-like signals) 2) Affinity head(s) for affinity_pred_value and affinity_probability_binary.

In this implementation, protein and ligand are processed in the same forward pass. This is why it is called full-atom cofolding rather than docking a fixed receptor.

How protein is represented

From source behavior (tokenizer + feature pipeline) in this project setup.

Protein token

One token per standard residue (20 canonical amino acids + unknown token).

  • Identity: residue token from chain sequence (e.g. ALA, LYS).
  • Geometry anchors: CA as center and C as disto atom for that residue.
  • Frame: local N-CA-C frame for each residue used by geometric blocks.
  • Masking: resolved and disto-present flags per residue.
  • Connectivity: residue-neighbor graph is added for the pairwise embedding and pair masks.

Ligand token

Ligand is usually non-polymer; each atom becomes one token.

  • Token granularity: one atom = one token.
  • Identity token: ligand atoms in non-polymer chains use the protein UNK residue token namespace but retain atom identity via atom fields.
  • Center/disto: both use the same atom coordinate for that token.
  • Bonds: chemical bonds and explicit connections are added to token-bond graph.
  • Frame: computed geometrically from nearest neighbors inside ligand because there is no N/CA/C template.

Practical interpretation: in pairwise updates and downstream diffusion, protein residues are compact tokens while ligand is an atom-level graph. The model is therefore not treating a ligand as one residue-level node.

Token-level mapping used internally

Field Purpose in model
sym_id, asym_id, entity_id Group and chain-level identity used for relative positional logic and masks.
mol_type Distinguishes protein/DNA/RNA/nonpolymer; affinity path uses this to define receptor-vs-ligand interactions.
token_pad_mask Suppresses padded positions in s/z attention and outputs.
token_bonds + type_bonds (optional) Injects local chemical/chain topology into initial pair embedding.
affinity_token_mask, affinity_mw Selects ligand for the affinity head and applies optional MW correction.

How the affinity head reads the complex

Signal path

1) Trunk outputs pair representation z (N x N x d)
2) Build receptor mask: mol_type == PROTEIN
3) Build ligand mask: affinity_token_mask == true
4) Keep only cross terms + ligand-ligand terms
5) Pass masked pair features + predicted coordinates to AffinityModule
6) Produce two outputs:
   - affinity_pred_value (regression scale, IC50 proxy)
   - affinity_logits_binary -> sigmoid -> affinity_probability_binary

Why two affinity outputs?

They are separate supervisory tasks:

Value head continuous potency comparison (e.g., relative ranking within active analogs).

Binary head binder vs non-binder discrimination.

Inference logs both so you can decide which matches your question.

For your benchmark: what to verify first

  • Run one TYK2 complex end-to-end and confirm both structure + affinity JSON fields are produced.
  • Inspect that ligand tokens are not accidentally absent (missing atomization or tokenization fail).
  • Check if affinity corresponds to the intended binder chain via affinity property in YAML.
  • Track stochasticity: repeat seed or sample count changes should alter structure spread, not just affinity noise.

This is not a physics/thermo free-energy calculation. Outputs are model scores at inference; they must be validated against controlled assay-consistent benchmarks before biological claims.

Graph view of the architecture and diffusion decoder

Paper-style interpretation of the diffusion decoder:

  • Diffusion conditioning builds context from trunk features and atom neighborhoods, then injects it as biases.
  • Diffusion loop iterates over sigma levels; each step denoises coordinates from noisy atoms, optionally applies guidance, then computes the next noisy/cleaned coordinates.
  • Within a step: encoder → token transformer → decoder, with preconditioning scalars c_in, c_skip, c_out, and c_noise.
